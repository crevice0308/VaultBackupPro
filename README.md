# VaultBackupPro

**VaultBackup Pro 1.3.0** は、Minecraft サーバー向けの無料・GPLv3 バックアッププラグインです。「復元予約 → 自分で通常停止 → 完全終了後に復元 → 手動起動」に対応し、日本語・英語の表示を選べます。

配布 JAR は **VaultBackupPro-1.3.0.jar** です。公開しているソースをそのままビルドしたもので、難読化していません。このリポジトリに対応ソースとビルド手順を含みます。配布物の識別は release/SHA256SUMS.txt と [検証結果](TEST-RESULTS.md)、ソース・公開ファイル名については [配布情報](PUBLICATION-NOTES.md)、1.3.0 の変更点は [変更履歴](CHANGELOG.md) を確認してください。

English guide: [QUICKSTART-EN.md](QUICKSTART-EN.md).

## プレリリース（テスト版）・必須の起動条件

この 1.3.0 はプレリリースのテスト用配布です。1.3.0 の JAR では実サーバーでの試験を実施していません（サーバーの起動に Minecraft EULA への同意が必要なため）。1.3.0 について行ったのは、ビルド時の検査と、サーバーを起動しない隔離試験だけです（結果は TEST-RESULTS.md）。本番環境で使う前に、試験環境でバックアップと復元を必ず確認してください。

ホストの自動再起動を無効にし、復元ヘルパーの完了と終了を確認してから手動起動してください。復元処理中に別のサーバーを起動する運用は未対応です。1.2.0 の実サーバー試験では、Paper がプラグインの停止要求後にもワールドを書き込むことが観測されており（1.3.0 では再試験していません）、プラグインだけではその競合によるデータ破損を防げません。ホスティング側の設定を確認できない環境で本番安全を保証しません。

## 対応環境
Paper / Purpur / Spigot、Minecraft Java 26.2 以降、Java 25。Folia など領域分割型のサーバーには対応していません。ビルド時に Spigot API 26.2・26.3 と Paper API 26.2・26.3 の 4 つに対してコンパイルとリンク検査を行っています。26.3 より新しいバージョンでは、未検証である旨の警告を表示して動作します。PaperMC は 26.2 のサポートを 2026-11-03 に終了しているため、26.3 を推奨します。

1.3.0 は実サーバーで試験していません。docs/RUNTIME-TEST-RESULTS.md と docs/test-evidence にある実サーバーの結果は過去の版（難読化ビルド）のもので、1.3.0 を対象としていません。Spigot の実機、Windows、実クライアントでの GUI 操作は未確認です。ビルドと隔離試験の結果、最終 JAR の SHA-256 は TEST-RESULTS.md と release/SHA256SUMS.txt を参照してください。

## 主な機能
- 管理者用のチェスト GUI、コマンド、バックアップ一覧・情報・容量表示
- 作成ボタンで即受付。保存中の案内をすぐ表示し、圧縮は非同期で実行
- サーバールートを対象とする ZIP バックアップ、SHA-256 と各ファイルの検証。`/backup verify` で全アーカイブを再検証
- 稼働中のサーバーでも作成を続行。コピー中に変化し続けたファイルは最後に読み取った内容で保存し、その件数を結果・一覧・GUI・ログに表示
- バックアップできないパスや保存先の空き容量不足は、理由を表示して中止
- 設定した件数・容量で自動整理。最後の 1 件も整理対象です
- 自動バックアップの間隔は最新のバックアップから数え、再起動をまたいで引き継ぎ
- 削除・復元予約は操作ボタンまたはコマンドで直接受付。追加確認画面なし
- 停止前に取り消せる復元予約。予約操作でサーバーを停止しません
- 完全な JVM 終了を確認する独立ヘルパー、元のサーバーツリーの退避、失敗時の保護
- サーバーの公開 API のみを使用。Paper・Purpur では Brigadier コマンドと Adventure コンポーネント、Spigot では plugin.yml のコマンドと ChatColor
- 日本語を標準に、設定で英語へ切替可能
- Discord 通知は任意設定。標準では無効です

## 最初に読む文書
INSTALL.md → COMMANDS.md → CONFIGURATION.md。運用前に TEST-RESULTS.md、KNOWN-LIMITATIONS.md、docs/OFFLINE-RESTORE.md を必ず確認してください。

1.2.x から更新する場合、バックアップと状態ディレクトリはそのまま使えます。config.yml の変更は不要です。手順は INSTALL.md の「更新時の注意」を参照してください。

## 操作時の注意
削除は追加確認なしで実行され、取り消せません。最後のバックアップも手動・自動整理で削除できるため、0 件になる場合があります。独立したバックアップも保管してください。

復元ボタンを押すと検証後すぐに次回停止時の復元が予約されます。不要になったら停止前に `/backup restore cancel` を実行し、取消完了を確認してください。

復元を予約したまま `/reload` やプラグインの再読み込みを行うと、予約は取り消されます（サーバーは停止しません）。Spigot には停止中かどうかを確認する API がないため、予約中にプラグインだけを無効化し、その後 10 分以内にサーバーが異常終了した場合にも復元が適用され得ます。予約中はプラグインの再読み込み・無効化を行わないでください。詳しくは KNOWN-LIMITATIONS.md と docs/SPIGOT-COMPATIBILITY.md を参照してください。

## 大切な制約
稼働中のバックアップは、別プラグインのデータベースや外部書込みまで原子的に止めるファイルシステムスナップショットではありません。全ファイルが同じ時点の内容とは限らず、コピー中に変化し続けたファイルは内部で不整合の可能性があります。それらは個別に保存・停止してください。

復元は対象 ZIP に含まれるツリーでサーバールートを置き換えます。除外ファイルは新しいツリーへ混在させず、復元前の退避ツリーに残します。バックアップと復元状態はサーバールート外に置きます。サーバールートがマウントポイント（独立したボリューム）の場合や、親フォルダーに書き込めない場合は、復元を予約できません。ホスティング側の自動再起動・監視再起動を止め、ヘルパー完了前に再起動しないでください。

古いバックアップには、その時点のプラグイン JAR と設定も入っています。以前の版を含むバックアップを復元すれば、プラグイン自体も以前の動作・言語設定へ戻ります（1.2.x 以前のバックアップなら、難読化された旧版の JAR に戻ります）。復元後にどの改訂が入っているかを確認してください。

無料・オープンソースとして、ソースとビルド手順を同梱しています。配布する JAR は難読化していません（1.1.0〜1.2.1 は難読化していました。経緯は docs/OBFUSCATION.md）。ライセンスは **GPLv3（GPL-3.0-only）** です。LICENSE.txt と NOTICE.txt を確認してください。改変版の配布にも該当するソース提供・ライセンス維持の条件があり、商用利用・有償再配布自体は許可されます。実サーバーでの動作、実クライアント GUI 操作、Windows での実行などの未検証項目は別途確認が必要です。マーケットの審査合格やデータ損失がないことを保証するものではありません。
